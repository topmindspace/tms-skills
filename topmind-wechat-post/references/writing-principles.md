# 发文铁律：精炼客观 + 素材优先 + 研究深度

> 适用于 topmind-briefs / topmind-x-article / topmind-wechat-post。
> 触发技能时默认执行，无需用户每次声明。

## 一、默认写作模式：精炼客观

1. **文字精炼**：能一句话说清的不用两句；删一切"正确的废话"。
2. **陈述客观事实**：只写可核实的事；厂商数字标"厂商口径"；无法核实就删。
3. **不泛化**：不从单个案例跳到"行业趋势"；不从一次测试跳到"彻底改变"。
4. **不主观判断**：不写"令人惊艳""颠覆性""必看"这类无法验证的形容词。
   让事实自己说话。
5. **标题问句**：当核心判断尚未完全确定时，标题可用问句诚实表达不确定性
   （例：《一切皆插件之后：软件工具的 RSI 时刻？》），正文用证据把"问号"讲透，
   而不是用感叹号假装确定。

## 二、素材优先原则

1. **信息收集**：基于用户要求，做全面的信息和素材收集、整理、交叉比对核实。
2. **原图优先**：官方图表、第三方榜单、数据表格——尽量用原图，不手绘仿制。
3. **图说事实**：能用素材图片传达的意思，文字就少写。图承担数据，正文只解读。
   看图即知的事实（数字、趋势、结构）正文不再复述一遍，只写图看不出的解读和判断。
4. **素材排序**：官方产品截图 > 官方基准图 > 第三方榜单截图 > 权威媒体图表 > 自制图表。
   自制图只用于时间线、价格对比、总结盘点（无法找到原图时）。
5. **配图丰富度（主动挖掘）**：不要等"有图就用"，要主动找图——论文原图/图表、
   工具截图、评测基准原图、关键帖子截图、产品界面实拍。有信息量的段落尽量配图，
   装饰图一律不要。目标：读者看图能跟上 70% 的论证，文字负责剩下的 30%（判断与连接）。

## 二点五、可视化优先（写作铁律）

> 能用可视化传达的，不用文字啰嗦。这是 X 和公众号共同的内容要求。

1. **表格 > 段落**：对比类内容用简单表格，不写大段文字。
2. **列表 > 段落**：并列要点用列表，不写成长段。
3. **"概要 + 列表"**：信息密集的节，先给一句概要（这节的结论），再用列表展开论据。
   不写长段论述；非写不可的长段，拆成多个短段或转成"概要+列表"。
4. **图表 > 描述**：数据趋势用图表，图片用素材原图。
4. **卡片样式**：MD3 优雅风——不用任何衬条（左侧色条、顶部/底部横向线一律不用）；
   靠背景色调（tonal）+ 大圆角区分层级。表格用浅色风格：表头浅蓝底 + 蓝色文字，
   无网格线，行间用底部分隔线；宽表转卡片时同样浅色、无衬条、标题用蓝色强调。
5. **文字密度**：每段 ≤110 字；列表项 ≤70 字；健康密度 300-450 字/图。

## 三、研究探讨模式（用户做研究/思考时）

当用户给出主题 seed、问题、思考、启发、线索，要求探讨分析时：

1. **充分收集**：信息收集、整理分析、检索比对，一个都不能少。
2. **客观为基**：所有论述建立在核实过的事实上。
3. **主观有度**：可以有针对性的主观论述、论点、判断、分析——
   但必须：不肤浅、洞察深入、严谨、有思考、有全面性/系统性、
   角度有特点、有判断力。
4. **留白提问**：可以提出合理的问题留待后续交流或跟进；可以合理挑战既有观点。
5. **论文扩展**：有条件时，寻求高质量论文、研究报告，进一步分析扩展。

## 四、禁止清单

- ❌ 泛化扩展：从个案跳到全行业
- ❌ 主观陈述：无法验证的形容词和判断
- ❌ 编造数据：任何未经核实的数字
- ❌ 套话：正确的废话、社交垫词
- ❌ 浅层分析：只复述事实不给洞察（研究模式下）
